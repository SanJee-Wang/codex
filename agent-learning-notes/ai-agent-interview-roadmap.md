## 1. 这个 agent 的 7 条核心构建思维（总纲）

1. **Agent 是一个循环，不是一次调用。** 感知 → 决策 → 行动 → 观察，反复转直到「任务完成」。这是所有 agent 的地基。
2. **工具是手，但每只手都要「可控」。** 编排的核心不是「能调什么」，而是审批、沙箱、重试、降级——安全可控优先于能力。
3. **上下文是最贵的资源。** 每轮 prompt 是精心拼装出来的；超限后用 compaction 压缩。本质：在有限 token 预算里保住最重要的信息。
4. **多 agent 是分治，不是堆模型。** 主 agent 派生子 agent，隔离上下文、限制预算、回收结果。
5. **一切皆事件流。** 异步事件 + 状态机，支撑流式输出、取消、并发。
6. **安全是设计出来的，不是事后补丁。** 沙箱分层、命令策略、安全审查贯穿全程。
7. **记忆是分层的。** 会话历史（短期）→ compaction 摘要（中期）→ 持久化记忆（长期）。

## 2. 分模块精讲清单

每个模块按这个模板来：**核心思想 → 关键设计决策与 trade-off → 面试怎么考 → 我的讲解方式。**

### 模块 A · Agent 主循环（第一优先级，2~3 天）

- **核心思想**：一个 agent 的一次任务，是「模型决策 → 工具执行 → 结果回灌 → 再决策」的循环，直到模型判定「结束」。
- **关键设计决策**：
  - 循环的**停止条件**怎么设计（模型显式结束 / 步数上限 / 预算耗尽）。
  - 为什么**流式输出**（边生成边给用户）而不是一次性返回。
  - 工具结果**回灌**给模型时的消息结构（user / assistant / tool 角色）。
  - 一次任务里多次模型调用的**中间状态**存哪里。
- **面试怎么考**：用伪代码描述主循环；如何防死循环。
- **讲解方式**：我给你主循环的伪代码 + 时序图，再对照 Codex 的 `session` / `client` 模块，指出它和「教科书版」差在哪（预热连接、重试预算、取消）。

### 模块 B · 工具调用与编排（第一优先级，3~4 天）

- **核心思想**：模型只能「输出要调哪个工具 + 参数」，真正执行、管控、容错在编排层。
- **关键设计决策**：
  - 工具**注册与路由**：一堆工具怎么按名字找到实现。
  - **审批**：哪些操作要用户确认，哪些自动放行。
  - **沙箱升级重试**：执行被拒后，换更高权限的沙箱重试，但**不再重复审批**（靠缓存）——这个「授权与执行的分离」是精髓。
  - 工具 schema 怎么序列化成模型的 function calling 格式。
- **面试怎么考**：Function Calling schema 设计；审批状态流转；重试与幂等。
- **讲解方式**：重点讲 Codex 的 `orchestrator` 核心序列 `审批 → 选沙箱 → 执行 → 失败升级沙箱重试`，用流程图讲透。

### 模块 C · 上下文工程与压缩（第一优先级，3~4 天，最能体现深度）

- **核心思想**：模型的能力上限由「喂给它的上下文」决定；上下文又是最大成本，所以要「拼装 + 压缩」两手抓。
- **关键设计决策**：
  - 每轮 prompt 由哪些**片段**拼成（系统提示、用户目标、环境、记忆、多 agent 指令……）。
  - 上下文**超限**了怎么办：compaction——用模型把历史压缩成摘要，而不是简单截断。
  - compaction 的**触发时机**和 **token 预算**怎么算。
  - 压缩时**哪些必须保留**（用户目标、世界状态），哪些可以摘要。
- **面试怎么考**：上下文满了怎么办；为什么用摘要而非截断；token 预算怎么算。
- **讲解方式**：我讲清楚「为什么不能截断」的核心 trade-off，再对照 Codex 的 `context` / `compact` 模块讲它保了哪些、压了哪些。

### 模块 D · 多 Agent 编排（加分项，2~3 天）

- **核心思想**：把大任务**分治**给多个子 agent，而不是让一个 agent 硬扛。
- **关键设计决策**：
  - 子 agent 与父 agent 的**上下文隔离**。
  - 子 agent 的**预算限制**（token / 时间 / 成本），超了怎么办。
  - 父子 agent 的**通信机制**（消息 vs 返回值）。
  - **递归深度限制**（防止 agent 无限 spawn agent）。
- **面试怎么考**：怎么派生子 agent；上下文与权限如何隔离；预算如何限制。
- **讲解方式**：我讲「spawn 子 agent 的完整生命周期」，对照 Codex 的 `agent` 模块。

### 模块 E · 安全沙箱（选读，面 AI 安全 / infra 方向）

- **核心思想**：让 agent 执行代码 / 命令是危险操作，安全要在设计里，而不是事后。
- **关键设计决策**：沙箱分层（不同隔离强度）、命令执行策略（ban 列表）、安全审查（guardian）。
- **面试怎么考**：agent 执行代码有哪些风险；沙箱分几层、各隔离什么。

### 模块 F · MCP（选读，面工具 / 插件生态方向）

- **核心思想**：用一套**开放协议**让外部工具可插拔接入，而不是写死内置工具。
- **面试怎么考**：MCP 是什么；外部工具如何接入。

## 3. 面试高频题清单（20 道，按模块）

### Agent 主循环
1. 用伪代码描述一个 Agent 主循环。
2. 循环的终止条件有哪些？如何防止死循环 / 空转？
3. 流式输出怎么实现？SSE 和 WebSocket 怎么选？
4. 工具调用结果怎么回灌给模型？消息结构如何设计？

### 工具与 Function Calling
5. Function Calling 的 schema 怎么设计？参数校验在哪做？
6. 哪些工具操作需要用户审批？审批状态如何流转？
7. 工具执行失败如何重试？重试策略与幂等性怎么保证？
8. 工具的沙箱 / 权限如何隔离？

### 上下文工程
9. 一帧 prompt 由哪些部分组成？各占多少 token？
10. 上下文窗口满了怎么办？简述 compaction 流程。
11. compaction 的触发时机和预算如何计算？
12. 哪些上下文必须保留、哪些可丢弃，判断依据是什么？

### 多 Agent
13. 主 agent 如何派生子 agent？生命周期如何管理？
14. 父子 agent 的上下文与工具权限如何隔离？
15. 子 agent 的预算（token / 时间 / 成本）如何限制？

### 记忆与历史
16. 对话历史如何持久化？如何恢复 / 重建一次会话？
17. 「记忆」和「上下文窗口」的区别是什么？

### 安全
18. AI Agent 执行代码 / shell 命令有哪些安全风险？如何缓解？
19. 沙箱有哪些层级？各自隔离什么？

### 工程思维
20. 为什么生产级 Agent 常用异步 + 消息队列（actor 模型）？取消（cancellation）如何传递？

## 4. 动手实践：Python mini agent（把思想内化的唯一方式）

**这是整个学习里最重要的一步。** 看完前三个模块后，用 Python 写一个 ~200 行的 mini agent：

1. **Agent 主循环**：模型调用 → 工具执行 → 回灌，直到结束。
2. **3 个工具**：shell 执行、文件读写、web 搜索。
3. **一个简单上下文裁剪 / 摘要**。
4. **一个可选的最小子任务委派**。

写完再写一份 **对照笔记**：`我的 mini 版 vs Codex 生产版` 各差在哪（错误处理、取消、流式、审批、沙箱……）。这份笔记就是面试时「我看过 Codex 源码 + 自己也实现过」的硬证据。

> 技术栈建议：`openai` SDK（Responses API）+ `asyncio`，不需要任何框架。
